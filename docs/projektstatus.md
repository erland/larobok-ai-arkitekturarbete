## Introducerade begrepp
| Begrepp | Kapitel | Kort definition |
|---|---|---|
| AI-förmåga | 1 | Organisatorisk och teknisk förmåga att använda AI för ett syfte. |
| AI som arbetsverktyg | 1 | Användning av AI för att stödja arkitektens egen analys, dokumentation och beslutsberedning. |
| AI som systemkomponent | 1 | AI som del av en teknisk lösning, exempelvis klassificering, beslutsstöd eller generering. |
| AI som strategisk förändringskraft | 1 | AI som påverkar verksamhetsförmågor, styrning, sourcing, kompetens och ansvar. |

| AI-augmented architecture | 3 | Arkitekturarbete där AI används för att förstärka analys, dokumentation, modellering eller beslutsberedning. |
| Promptad analys | 3 | Arbetssätt där arkitekten styr AI genom tydliga frågor, avgränsningar, roller, kriterier och kontext. |
| Mänskligt ansvar | 3 | Principen att ansvar för arkitekturbeslut, riskbedömning och rekommendationer inte kan delegeras till AI. |
| Provenance | 3 | Spårbar beskrivning av ett underlags ursprung, bearbetning och granskningskedja. |
| Capability architecture | 2 | Arkitektur som utgår från verksamhetsförmågor snarare än enskilda system. |
| Decision intelligence | 2 | Strukturerat arbete med hur beslut fattas, förbättras, automatiseras eller stöds med data, analys och AI. |
| Value stream | 2 | Värdeflöde som visar hur värde skapas från behov till resultat. |
| AI governance | 4 | Styrning av AI över livscykeln. |
| Data product | 7 | Förvaltningsbar datatillgång med syfte, ägare, kvalitet, metadata, åtkomstregler och livscykel. |
| Metadata | 7 | Data om data, exempelvis definitioner, klassning, ägare, kvalitet, ursprung och användningsvillkor. |
| Data lineage | 7 | Spårbarhet för var data kommer ifrån, hur den har förändrats och var den används. |
| Data readiness | 7 | Bedömning av om data är tillräckligt mogen, styrd och begriplig för en viss AI-användning. |

| AI-säkerhetsarkitektur | 10 | Arkitektur för att skydda AI-förmågor genom kontroller för data, åtkomst, modell, kontext, instruktioner, utdata, loggning och incidenthantering. |

| AI operating model | 11 | Modell för hur organisationen styr, driver, följer upp och avvecklar AI-förmågor i praktiken. |

| Förmågeägare | 11 | Roll eller ansvarsfunktion som äger syfte, nytta, risk och uppföljning för en AI-förmåga. |

| Policy layer | 12 | Arkitekturlager som omsätter styrning, informationsklassning, åtkomst, modellregler och användningsregler till praktiska kontroller. |
